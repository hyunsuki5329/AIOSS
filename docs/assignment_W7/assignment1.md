# 과제 1: 기본 CI 구축

## PRACTICE

## MISSION 01
### Hello, CI Pipeline!

가장 기본적인 형태의 CI 워크플로우를 직접 작성해보며 자동화의 기초를 다집니다.
코드가 푸시될 때마다 자동으로 실행되는 파이프라인을 경험해보세요.


## 수행 단계

### 1) 프로젝트 생성
간단한 Node.js 또는 Python 프로젝트를 생성합니다.
npm init 또는 requirements.txt를 포함하여 의존성 관리 환경을 만드세요.

### 2) 워크플로우 파일 작성
저장소 루트에 .github/workflows/ci.yml 파일을 생성하고,
on: push 이벤트를 트리거로 설정합니다.

### 3) 자동화 단계 구성
Lint(코드 검사)와 Test(단위 테스트)를 실행하는 Job을 정의합니다.
actions/checkout과 언어별 setup 액션을 사용하세요.

### 4) 실행 및 검증
코드를 GitHub에 Push한 후, 저장소의 Actions 탭에서 워크플로우가 자동으로 실행되고
성공(녹색 체크)하는지 확인합니다.

## 검증 체크리스트
- 프로젝트에 기본 의존성 파일이 있다
- .github/workflows/ci.yml 파일이 존재한다
- push 시 CI가 자동 실행된다
- Lint와 Test 단계가 포함되어 있다
- Actions 탭에서 성공 실행 이력을 확인했다

## 에이전트 프롬프트

아래 프롬프트를 에이전트에 그대로 입력해서 과제 1을 수행하세요.

```text
너는 GitHub Actions CI 구축을 도와주는 실습 코치다.

[목표]
- 이 저장소에 기본 CI를 구축한다.
- push 이벤트에서 자동 실행되는 워크플로우를 만든다.
- Lint + Test 단계를 포함한다.

[작업 지시]
1) 프로젝트 타입 자동 판별
- Node.js 프로젝트면 package.json 기준으로 설치/테스트 명령을 사용한다.
- Python 프로젝트면 requirements.txt 또는 pyproject.toml 기준으로 설치/테스트 명령을 사용한다.

2) 워크플로우 파일 생성
- 경로: .github/workflows/ci.yml
- 트리거: on: push
- 공통 단계:
	- actions/checkout
	- 언어별 setup 액션
	- 의존성 설치
	- Lint 실행
	- Test 실행

3) 실패 방지
- Lint 또는 Test 스크립트가 없는 경우, 안전한 대체 명령을 제안하고 워크플로우에 반영한다.
- 명령이 불명확하면 최소 동작 가능한 방식으로 작성한다.

4) 검증
- 문법 오류 없는 YAML인지 확인한다.
- 로컬에서 가능한 범위의 사전 검증을 수행한다.

[출력 형식]
- 최종 변경 파일 목록
- ci.yml 전체 내용
- 실행/검증 방법 3줄 요약
- 체크리스트 충족 여부 (각 항목 O/X)

[품질 기준]
- 불필요한 복잡성 없이 초심자도 이해 가능한 구성
- 주석은 필요한 경우에만 짧게 작성
- 기존 파일/구조를 임의로 파괴하지 않음
```
